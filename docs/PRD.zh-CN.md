## 1. 产品决策摘要

拾文帮助用户在自己选择的文件夹内，通过文件名或文档正文找到资料，并在结果中直接看到命中段落。

第一版打通一个完整闭环：**选择文件夹 → 本地建索引 → 输入关键词 → 查看命中上下文 → 打开原文件**。

核心决策：

1. 首版支持文字版 PDF、Markdown、DOCX；扫描页明确显示“需要文字识别”，离线 OCR 后续提供。
2. 中文全文搜索是基础能力，必须覆盖双字词、连续中文、中文与英文混排。
3. 只读取用户明确添加的目录，不默认扫描整盘；可排除子目录、暂停索引、清除数据。
4. 索引主要保存在磁盘上，后台任务有资源上限；搜索优先于后台解析。
5. 搜索结果以命中段落为核心，提供来源路径、文件类型与可验证的位置。
6. 不要求账号，不依赖云端服务，不自动上传文件、路径、正文、搜索词或诊断数据。
7. 保留已设计的三栏界面，玻璃效果集中在导航与搜索区域，正文清晰度优先。
8. 第一版不做文件移动、重命名、批量删除、知识库编辑或 AI 问答。

## 2. 背景与定位修正

### 2.1 用户真正遇到的问题

用户记得文件里的某句话，却忘记文件名和位置。文件分散在工作资料、个人笔记和阅读目录中，逐个打开确认成本高；搜索未命中时，也难以判断是没有内容、未被索引，还是文件解析失败。

“更容易找到并确认那份文档”是本产品需要验证的价值，而不仅是增加一个搜索框。

### 2.2 不以错误的竞品假设立项

Windows Search 官方说明包含文本内容索引；Apple 也说明 Spotlight 会索引设备内容。不能把“系统搜索只能搜文件名”写成产品事实。[Microsoft 官方说明](https://support.microsoft.com/en-us/windows/experience/performance-optimization/search-indexing-in-windows)、[Apple 官方说明](https://support.apple.com/en-gb/102321)

Everything 官方文档提供 `content:` 内容搜索；其 FAQ 描述了未建立内容索引时的速度限制，另外的选项文档还列出需要 Everything 1.5 的内容索引功能。竞品评估必须注明实际版本和配置，不能笼统写成“Everything 不支持全文搜索”。[Everything FAQ](https://www.voidtools.com/faq/)、[Everything 内容索引选项](https://www.voidtools.com/support/everything/options/)

拾文拟验证的差异化是：**无需理解索引配置、中文搜索表现稳定、直接展示相关段落、明确解释漏搜原因，并让资源与隐私可控。**这些是产品方向，不代表已证明优于现有工具。

## 3. 用户与使用场景

| 用户 | 典型资料 | 核心任务 |
| --- | --- | --- |
| 日常办公用户 | 方案、会议记录、内部说明 | 用记得的内容找回历史文件 |
| 学生与研究人员 | 文字版论文、读书笔记、课程文档 | 找到某个概念出现在哪份资料、哪一页 |
| 开发者与个人知识管理用户 | Markdown、技术文档、产品资料 | 跨目录检索中文、英文术语和技术词 |

核心场景：

- 输入“离线部署”，找到文件名不含此词、正文包含此词的 PDF。
- 输入“预算 审批”，找到同时包含这两个条件的文档。
- 只在“工作资料”中搜索，并进一步筛选 Word 文件。
- 查看某份 PDF 的多处命中，无需先打开外部阅读器。
- 修改一份笔记后，稍后再次搜索即可看到最新内容。
- 搜不到扫描件时，看到明确原因，而不是误以为文件不存在。

| 类型、目录筛选与排序 | P0 | 相关度 / 最近修改 |
| 收藏 | P0 | 收藏文件，不复制原文件 |

## 5. 用户流程与页面结构

### 5.1 首次使用

1. 欢迎页说明：“选择文件夹，搜索文档里的文字。文件和索引都保存在这台电脑。”
2. 提供“选择文件夹”，以及可勾选的桌面、文档目录快捷入口；不预先读取目录正文。
3. 展示已选目录、支持类型和排除入口；用户点击“开始建立索引”。
4. 枚举与解析并行进行，立即进入主界面；已处理文档可以先搜。
5. 显示“已发现 420 份，已处理 168 份”；枚举结束前不展示虚假的总进度百分比。
6. 完成后给出可展开的统计，例如“可搜正文 392 份，部分可搜 8 份，仅文件名可搜 20 份”，并提供原因列表。

失败不阻塞其他文件。拒绝系统目录访问权限后，给出重新选择或重试入口，不循环弹权限请求。

### 5.2 日常使用

打开应用 → 聚焦搜索 → 输入关键词 → 浏览结果摘要 → 选中预览 → 切换命中位置或打开原文件。

搜索与筛选条件在切换结果时保留；清空搜索词不自动清除筛选。无关键词时显示当前范围内最近修改的文档，不出现空白主界面。

### 5.3 页面清单

| 页面 / 区域 | 内容与操作 |
| --- | --- |
| 首次引导 | 选择范围、支持格式说明、启动索引 |
| 搜索主界面 | 左侧范围与收藏；中间搜索结果；右侧内容预览 |
| 文件夹管理 | 添加、移除、排除规则、目录访问状态 |
| 索引状态面板 | 队列进度、暂停恢复、失败项、重试、最近更新时间 |
| 设置 | 外观、资源模式、数据目录占用、清除本地数据 |
| 异常状态 | 权限、无文本、损坏、超限、待下载、目录失联 |

概念稿中的“示例预览”在正式版移除。文档数、索引状态等均由真实数据驱动，不保留演示数字。

## 6. 功能需求与验收标准

### F01 · 文件夹范围管理（P0）

- 通过系统文件夹选择器添加一个或多个目录；递归处理符合规则的文件。
- 相同目录与父子重叠目录不得重复索引同一份文件。
- 默认排除系统目录、隐藏目录、版本控制目录、依赖目录、临时文件和拾文自身数据目录；展示可理解的排除说明。
- 支持手动排除子目录；排除规则优先于包含规则。
- 首版不跟随目录符号链接，不跨出已授权范围；界面中明确说明。
- 云盘占位文件不主动下载。已完整落地的本地文件可处理；未落地文件标记“请先在原应用中下载”。
- 移除目录时，只移除拾文中的索引和该范围专属的收藏引用，不删除、移动或改写原文件。仍属于其他已选范围的文件继续保留。

验收：同一目录添加两次无重复结果；排除子目录后，其内容立即退出检索，后台清除派生数据；原文件内容、路径和修改时间不因本操作改变。

### F02 · 文档解析（P0）

| 格式 | 必须支持 | 首版限制与提示 |
| --- | --- | --- |
| PDF | 可提取文字；按物理页保存位置；能处理常见中文与英文 | 图片内文字不识别；复杂多栏阅读顺序不保证完全还原 |
| Markdown | UTF-8 文本；标题、段落、列表、表格文本、代码块；保留源文件行号 | 不执行 HTML / 脚本，不请求远程图片；非 UTF-8 编码明确提示 |
| DOCX | 正文段落、标题、普通表格单元格 | 不含旧版 .doc；不承诺批注、文本框、嵌入对象和图片文字；不执行宏或外部关系 |

- PDF 同时含文字页与图片页时，文字页照常索引，标记“部分页面无可提取文字”。
- 无法确定是否为扫描件时，使用“未提取到文字，可能需要 OCR”，不把空白页一律称为扫描件。
- DOCX 预览使用提取文本，不宣称还原 Word 排版；不生成推测页码。
- 加密、损坏、权限不足、暂被占用、超过限制等情况有独立状态。
- 无正文但已获得名称和路径的文件仍可通过文件名搜索，结果中标注“正文不可搜”及原因。
- 默认自动解析上限暂定：单文件 100 MiB、PDF 1,000 页、提取后正文 10 MiB；超限转为“仅文件名可搜”，不静默截断。调整上限前显示资源影响。
- 解析按文件隔离，默认单任务超时 60 秒；超时标记并继续后续文件。具体值须在解析样本上校准。

验收：标准样本中的正文、PDF 页码与 MD 行号正确；DOCX 表格内关键词能找到；加密文件不导致应用退出；混合 PDF 显示部分可搜状态。

### F03 · 本地索引与更新（P0）

- 首次建立索引、文档修改后更新、文件删除后撤销结果。
- 监听文件变化，并在应用启动、从休眠恢复及用户手动刷新时补扫；监听事件不作为唯一事实来源。
- 对连续写入做稳定性等待，避免在文件保存中途读取半成品。
- 元数据用于筛选疑似变化，必要时结合内容摘要验证；不能只依赖修改时间判断所有情况。
- 同一文件的新索引就绪后原子替换旧版本，查询不读到混合版本。
- 文件已知发生变化但未更新时，结果标记“内容待更新”；预览不能把旧缓存描述为当前原文。
- 在支持稳定文件标识的平台内，重命名保留收藏；无法可靠关联的移动按“旧文件失效、新文件加入”处理，不猜测身份。
- 文件夹失联与文件被确认删除分开处理。失联期间默认从常规结果排除其缓存正文，恢复后重新核对；权限撤销同样退出正文检索。
- 支持暂停、继续、单项重试、目录重试。暂停索引后，已有且仍有访问权限的内容可检索。
- 应用异常退出后恢复任务；重建索引不能先销毁唯一可用版本，使用后台新版本并在成功后切换。

验收：新增、修改、删除、重命名、休眠恢复、异常退出与重启均有测试样本；不产生重复项、永久陈旧结果或整库丢失。

### F04 · 查询规则与中文检索（P0）

**默认搜索范围：文件名与支持格式的可提取正文。**路径通过目录筛选使用；不暗中把路径命中混入正文结果。

| 用户输入 | 预期行为 |
| --- | --- |
| `离线部署` | 匹配连续中文片段，正文中出现该片段即可找到 |
| `部署` | 支持常见双字词，不因中文无空格而漏搜 |
| `预算 审批` | 同一文档必须满足两个条件；结果提供能解释各条件的摘要 |
| `"offline deployment"` | 连续短语匹配；大小写不敏感，连续空白规范化 |
| `PDF 索引` | 支持中英文混排与组合条件 |
| `<script>` / `C++` | 作为用户文本安全处理，不执行，也不直接暴露底层查询语法 |

- 默认英文大小写不敏感；保留可读原文用于高亮。
- 不默认进行简繁转换、拼音搜索、同义词扩展和模糊纠错，避免结果含义不清。
- 首版纯单字符查询显示“请输入至少 2 个字符”；不静默切换为文件名搜索。双字词必须支持；单字需求进入后续评估。
- 对引号不完整或输入过长给出明确提示，不暴露数据库错误。
- 输入停止约 180 ms 后触发搜索；中文输入法组词期间不发起无意义查询，候选文字提交后再查。
- 新请求取消旧请求或丢弃旧结果，禁止快速输入时显示回退的结果。
- 过滤与排序改变后从结果顶部展示；结果按文件聚合，一份文件只显示一行。

验收：准备至少 100 条标注查询，覆盖中文双字词、连续中文、中英混合、短语、标点和特殊字符；所有明确包含精确短语的标准样本必须召回。

### F05 · 结果排序、摘要与筛选（P0）

- 每条结果展示：文件名、格式、1–2 段命中摘要、相对目录、修改时间、索引异常标记（如有）。
- 正文命中、文件名命中分别可解释；仅文件名匹配时标注“文件名匹配”，不伪造正文摘要。
- 高亮来自真实命中文本，不生成或改写文档内容。
- 提供全部 / PDF / Markdown / Word 筛选；与目录、收藏范围可组合。
- 提供相关度与最近修改排序。相关度综合文件名匹配、连续短语、正文词频与词稀有度；具体权重由查询样本评估确定。
- 最近修改按文件时间排序，与拾文索引时间分开。
- 大量结果分页或虚拟化展示，首批 50 项；首批加载不必等待所有结果渲染。
- 未完成总计数时使用“已找到至少 N 份”，不能用估计值伪装精确数量。
- 零结果状态保留搜索条件，提示检查筛选，并显示当前是否仍有待处理或正文不可搜文件。

验收：每个摘要都能在对应原文找到；组合筛选结果正确；一个文件多个命中不会占满多行结果。

### F06 · 文档预览与打开（P0）

- 单击结果显示预览，并保留列表位置；双击或使用“打开原文件”调用系统默认应用。
- 内置 PDF 预览定位物理页；命中坐标可靠时高亮，无法可靠映射时退回该页文本预览，不绘制错误标记。
- Markdown 使用安全渲染与源行号定位；DOCX 使用带段落位置的提取文本。
- 支持上一处 / 下一处命中，显示当前序号与总数。
- 提供“在文件夹中显示”和“复制路径”；复制操作只响应用户点击。
- 外部 PDF 阅读器如支持定位则传页码，否则只打开文件；DOCX 外部应用不承诺段落或页码定位。
- 打开前复查文件是否存在与是否可访问；失效时显示状态，并触发索引核对。
- 外部网页链接与嵌入内容不自动加载；预览不执行脚本，不触发云盘下载。

验收：PDF 内置定位准确；DOCX 不显示伪造页码；外部应用不可用、文件被删除、权限变化时都有明确反馈。

### F07 · 收藏与轻量管理（P0）

- 支持收藏 / 取消收藏；状态重启后保留。
- 收藏保存文件引用，不复制正文、不生成额外文档副本。
- 收藏页复用同一搜索、筛选与预览体验。
- 失效文件在收藏中保留名称与“文件不可用”提示，允许移除引用；不保留可搜索的过期正文。
- 第一版不提供标签系统与对原文件的写操作。

验收：收藏切换即时生效；重启不丢失；文件失效后不会打开错误路径或显示缓存为现文。

### F08 · 状态、错误与恢复（P0）

全局状态：未设置范围 / 正在发现 / 正在索引 / 已暂停 / 已完成 / 需要处理。

文件状态：等待处理 / 处理中 / 正文可搜 / 部分正文可搜 / 仅文件名可搜 / 待更新 / 当前不可用。

| 情况 | 建议提示 | 可执行操作 |
| --- | --- | --- |
| 未添加目录 | 添加一个文件夹，开始搜索文档里的文字 | 选择文件夹 |
| 部分索引完成 | 已处理 168 份，更多内容正在加入 | 继续搜索 / 暂停 |
| 无可提取文字 | 未提取到文字，可能需要 OCR；目前可搜文件名 | 查看原因 / 打开文件 |
| 密码保护 | 此文件需要密码，正文暂不可搜 | 用原应用打开 |
| 权限不足 | 无法读取这个文件夹 | 重新授权 / 移除范围 |
| 文件占用 | 文件正在使用，稍后重试 | 重试 |
| 超过解析限制 | 文件超过当前处理上限，正文暂不可搜 | 查看限制 / 调整后重试 |
| 磁盘空间不足 | 已暂停建立索引，已有结果仍可使用 | 清理空间 / 继续 |
| 索引损坏 | 索引需要修复，原文件不受影响 | 修复 / 重建 |

失败列表允许按原因筛选；批量重试不重复处理已成功且未变化的文件。默认日志保存 7 天，上限 20 MiB，滚动清理。

### F09 · 隐私与本地数据（P0）

- 核心功能在断网环境可用；无需登录或联网激活。
- 文档、提取文本、索引、收藏与设置均保存在当前操作系统用户的数据目录。
- 本地索引可能包含敏感原文片段，享有与个人文档相同的保护要求；界面不能把“离线”解释成“已加密”。
- 首版不承诺应用级索引加密；使用系统用户权限隔离，并建议配合系统磁盘加密。应用不主动写入共享或云同步目录。
- 日志默认不保存正文、搜索词和完整路径；诊断导出由用户主动触发，并提供导出内容说明。
- 首版不启用遥测和自动崩溃上传，不自动检查更新；后续更新能力须单独设计联网说明。
- 设置提供“清除全部本地数据”：清除索引、文本缓存、收藏、设置和日志，同时停止队列；明确保留原文件。
- 目录移除后先立即取消其数据的可查询性，再清理数据库、缓存和日志关联信息。
- 数据清理需要处理数据库日志文件与临时文件；不承诺 SSD 上的取证级安全擦除。

验收：在阻断外网且记录应用网络行为的测试中，首次索引、搜索、预览和重启均成功；无应用主动对外请求。清理后重启回到首次引导，原文件哈希不变。

## 7. 视觉与交互设计要求

以已展示的「拾文」概念稿为方向：安静、清晰、接近原生桌面工具。

| 项目 | 要求 |
| --- | --- |
| 主布局 | 左侧范围导航，中间结果列表，右侧预览；列宽可调整 |
| 搜索框 | 位于主区域顶部，默认聚焦；清空按钮、类型筛选与范围状态清楚 |
| 视觉层级 | 命中摘要优先于装饰；名称其次，路径与时间为辅助 |
| 玻璃效果 | 仅用于导航、搜索区等少量区域；避免整页模糊与持续动画 |
| 正文区 | 实色背景、足够对比度；关闭透明效果后功能与层级保持完整 |
| 主题 | 跟随系统 / 浅色 / 深色；用户设置本地保存 |
| 动效 | 选择、预览切换约 120–200 ms；无循环漂浮和粒子动画 |
| 字体 | 随平台使用系统中文字体；正文不依赖联网字体 |
| 尺寸 | 主窗口以约 1,200 × 780 为设计基准；窄于 960 px 时预览转为可切换面板 |

键盘规则：应用内 `Ctrl/Cmd + K` 聚焦搜索；列表上下键切换结果；Enter 打开选中文档；Tab 按逻辑顺序移动；Esc 先关闭临时面板，不意外丢失搜索条件。

高 DPI、125% / 150% 缩放与长中文路径必须测试。系统不支持透明或用户关闭透明时，使用实色回退，不影响可用性。

## 8. 轻量与性能验收目标

### 8.1 统一测试口径

- 基准机器：4 核 CPU、8 GB 内存、SSD；Windows 与 macOS 分别记录实际型号、系统版本和测量方法。
- 标准语料：10,000 份支持格式的文档，PDF / MD / DOCX 约为 40% / 40% / 20%，提取后文本合计约 100 MiB，原文件总量不超过 2 GiB；不含 OCR。
- 单独记录中文文本比例、PDF 页数分布和大文件比例，避免仅以文件数量比较。
- 测量时记录语料清单及其摘要；冷热缓存结果分开，搜索耗时与输入防抖分开。
- 异常文件、扫描件、超大文件另成压力集，不通过从标准语料剔除正常慢文件来美化结果。

### 8.2 拟定发布门槛

| 指标 | 初始目标 | 口径 |
| --- | --- | --- |
| 热搜索 | P95 ≤ 300 ms | 提交查询到首批 50 项可交互，不含防抖；至少 100 条查询 |
| 冷搜索 | P95 ≤ 1 s | 独立冷启动测量；单独报告 OS 磁盘缓存状态 |
| 新增 / 修改入库 | 队列空闲时 ≤ 10 s | 小于 1 MiB 的正常 MD / DOCX，从写入稳定到新内容可搜 |
| 删除失效 | 监听正常时 ≤ 5 s | 本机在线目录，从删除到撤销可搜索正文 |
| 首次可搜 | ≤ 30 s | 标准语料上出现首批正文可搜结果，不代表整库完成 |
| 标准语料全量索引 | ≤ 15 min | 基准机器，正常资源模式，未被用户暂停 |
| 就绪后空闲内存 | ≤ 250 MiB | 应用及其工作进程合计驻留内存；共享页重复计入，保持口径一致 |
| 建索引内存峰值 | ≤ 600 MiB | 同上，包含解析子进程与预览进程 |
| 空闲 CPU | 60 s 平均 ≤ 1% 整机容量 | 无变更、无扫描、无动画，按总核心容量统一换算 |
| 磁盘占用 | 标准语料派生数据 ≤ 500 MiB | 索引、持久文本缓存、日志等合计，不含原文件和安装包 |
| 中文检索质量 | 精确短语测试召回率 100%；标注任务 Top-5 命中率 ≥ 90% | 基于支持解析范围的固定查询集，标注规则随报告提供 |

这些目标需在技术验证阶段校准。若未达到，明确记录原因、优化或缩小范围，不把目标数字作为宣传实测值。

### 8.3 资源控制规则

- 提供“低占用 / 标准”模式，默认标准；低占用模式串行解析，标准模式初始最多两个解析任务。
- 搜索优先调度；解析不得在 UI 线程执行。
- 暂停操作立即停止新任务；运行中的任务在检查点退出，无法退出时终止隔离任务，保留可重试状态。
- 低电量或系统省电模式下暂停新增后台解析，允许用户手动继续；已有索引可用。
- 设置中展示索引和缓存的实际磁盘占用，不能把磁盘索引大小称为内存占用。
- 大文档按页或块处理，避免把整库正文同时装入内存；预览缓存有明确上限。
- 安装包体积单独测量，计入必要运行时；不能通过隐藏首次联网下载来宣称离线可用。

## 9. 技术方案建议与待验证事项

本节用于限制风险，不替代技术设计。

建议采用本地桌面容器、轻量 UI、独立解析工作进程与磁盘数据库。可评估 Rust 本地核心搭配系统 WebView；若依赖额外运行时，离线安装路径须覆盖。

检索引擎可优先验证 SQLite FTS5，但不能将默认分词器直接当作中文搜索方案。SQLite 官方说明 `unicode61` 将连续字母或数字类字符组织为词元；`trigram` 使用连续三个字符，短于三个 Unicode 字符的全文查询存在限制。因此必须用中文双字词与混合文本样本验证，并比较自定义中文分词、字符二元索引等候选方案的召回率、体积和耗时。[SQLite FTS5 官方文档](https://www.sqlite.org/fts5.html)

建议的数据流：

```text
用户选择范围
  → 枚举与权限检查
  → 稳定文件队列
  → 隔离解析与文本位置映射
  → 中文 / 英文规范化和检索索引
  → 原子提交当前文件版本
  → 查询、摘要与安全预览
```

最小数据对象：

| 对象 | 必要字段 |
| --- | --- |
| 搜索范围 | 范围 ID、规范化路径、包含 / 排除规则、访问状态 |
| 文档 | 内部 ID、平台文件标识（如可用）、路径、格式、大小、修改时间、内容摘要、解析状态 |
| 文本块 | 文档 ID、版本、提取文本、原始位置、规范化文本到原文的映射 |
| 索引任务 | 文档 ID、任务版本、原因、状态、重试次数、错误码 |
| 收藏 | 文档 ID、创建时间、失效状态 |
| 本地设置 | 主题、资源模式、范围规则、数据版本 |

技术验证必须回答：

1. 双字中文检索能否在规定体积和内存下准确召回？
2. PDF 解析器对中文字体、多栏、换行和坐标映射的表现如何？
3. DOCX 解析能否覆盖正文与表格，并安全忽略外部引用？
4. 两个平台的文件监听在原子保存、休眠、权限变化时如何补偿？
5. 数据库重建与清除后，旧正文是否还会在缓存或事务日志中被应用查询到？
6. 桌面容器、解析器和发布依赖的许可、签名与离线运行条件是否满足？

## 11. 验证产品价值的方法

初期使用用户主动参加的可用性测试，不依靠后台遥测。

- 招募至少 5 位拥有实际 PDF / MD / DOCX 资料的目标用户。
- 每人完成“记得一句正文”“限定目录”“搜索失败找原因”三个任务。
- 记录首次成功搜索时间、是否能判断命中原因、是否误解索引状态，以及完成任务所需操作。
- 初始目标：至少 4/5 用户无需指导完成首个检索任务；至少 80% 的已索引查找任务在 30 秒内确认目标文档。
- 反馈只保存用户主动提供的记录；不收集其真实文档、路径或搜索词作为默认实验数据。
- 同一组任务可对照系统搜索或用户现用工具，但需记录版本与索引配置，避免无效比较。

## 13. 主要风险与取舍

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 中文检索方案不合适 | 关键词存在却找不到，或索引过大 | 优先完成双字词与混合文本验证，再定引擎 |
| PDF 提取质量差异 | 顺序异常、漏字、位置不准 | 用真实版式样本评估，回退到页级文本预览并明示限制 |
| 用户把扫描件当文字文档 | 对“全文搜索”产生误解 | 文件级状态透明；OCR 单独规划 |
| 文件监听丢事件 | 结果陈旧或重复 | 监听加补扫、版本校验、可见更新时间 |
| 玻璃效果占资源或影响阅读 | 违背轻量定位 | 小范围使用、支持关闭、不做持续动画 |
| 把离线等同于保密 | 本地索引泄露敏感片段 | 明示本地数据位置、权限与加密边界，可彻底清除应用数据 |
| 过早加入 OCR / AI / 管理功能 | 安装包、内存和研发范围膨胀 | 以全文检索闭环作为首版发布门槛 |
| 与现有工具差异不足 | 用户没有迁移动机 | 用实际任务验证“更省心、更容易确认命中”，而非宣传不存在的独占能力 |
