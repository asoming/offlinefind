# 性能实测：0.1.0b3

[English](PERFORMANCE-beta3.en.md)

2026-09-17，在一台 Ubuntu 电脑上完成了 **10,000 份合成文档**的全量索引和搜索测试，全部文档解析成功。实测发现排序阶段搬运正文的开销，beta.3 改为排序 ID / 路径后按需读取正文，保留范围检查、精确匹配与分页语义。

这是一条可复现的引擎基线，**不是完整桌面性能验收**。没有测量 GUI / WebKit、系统冷缓存、复杂真实文档或其他操作系统。

## 环境与语料

- Intel Core i9-14900HX，系统可见 32 个逻辑 CPU；内存约 15.32 GiB；本地 NVMe 文件系统。
- Ubuntu 22.04.5 x64，Linux 6.8.0-138-generic，glibc 2.35，Python 3.10.12。
- 7,000 份 Markdown、2,000 份 DOCX 解析夹具、1,000 份文本 PDF；每份约 10 KiB 中英文文本，共 102,950,000 字节（98.18 MiB）生成前文本。这不是文件总大小或最终提取文本大小。
- 文本高度重复，带独立编号和已知查询结果。PDF 使用 ReportLab 生成；DOCX 夹具是仅含 `word/document.xml` 的最小 ZIP，**不是完整 Office 文档包**，不覆盖真实 Word 文件的结构复杂度。
- 使用正式代码的独立解析进程：每份文档启动一个子进程，串行处理；没有用进程内解析器替代。
- 测试期间有开发工具和浏览器后台活动，结果会受机器负载与文件缓存影响。

## 索引与内存

| 指标 | 本次结果 |
| --- | ---: |
| 全量索引（不含语料生成） | 708.65 秒（约 11 分 49 秒） |
| 首批 50 份文档完成（采样） | 4.10 秒 |
| 索引数据库及 WAL | 244.45 MiB |
| 引擎和解析进程树 RSS 峰值（采样） | 94.16 MiB |
| 查询后进程树 RSS（基线轮次） | 66.89 MiB |

这些数值来自查询优化前的完整轮次；优化没有改变解析或索引格式。RSS 每 50 毫秒读取 Linux `/proc`，相加父进程及子进程，包含基准脚本和生成夹具时导入的库、Python 资源跟踪进程；可能重复计入共享页或漏掉短时峰值。**不含桌面窗口 / WebKit，也不等于应用的完整常驻内存。**

## 搜索：同一索引上的前后对比

每类查询 10 次，5 类共 50 次；读取第一页最多 50 条结果，并校验预期结果数量。P95 使用 nearest-rank，因此 10 个样本的 P95 是最大值。未清理操作系统文件缓存，两轮不是严格隔离的 A/B 实验。

| 查询 | 优化前中位数 / P95 | beta.3 中位数 / P95 |
| --- | ---: | ---: |
| `离线部署` | 418.49 / 443.95 ms | 170.57 / 176.37 ms |
| `"offline deployment"` | 501.92 / 508.83 ms | 266.25 / 280.96 ms |
| `预算 审批` | 415.48 / 418.43 ms | 166.34 / 168.53 ms |
| `SHIWENID009999`（唯一编号） | 32.80 / 33.19 ms | 31.39 / 31.70 ms |
| `不存在的基准短语` | 0.22 / 0.45 ms | 0.21 / 0.31 ms |

重开 SQLite 连接后的第一次 `离线部署` 查询：优化前 420.51 ms，优化后 171.55 ms。**这不是系统冷启动搜索。** 后一轮复用原索引，只重跑查询，没有再次索引 10,000 份文档。

原始数据：[完整基线](benchmarks/beta3-linux-10000-baseline.json)、[优化后查询](benchmarks/beta3-linux-10000-search.json)。基线中的 `version` 也是 `0.1.0b3`，因为两轮都发生在这一版本发布前；文件名区分测量阶段。

## 复现

在开发环境安装本仓库的 `.[dev]` 依赖后执行，目录必须是一个尚不存在的新路径：

```bash
python scripts/benchmark.py /tmp/shiwen-benchmark-10000
# 对同一语料、同一索引重新测量查询，写入独立 search-report.json：
python scripts/benchmark.py /tmp/shiwen-benchmark-10000 --queries-only
# 较短的流程自检（使用另一个新目录）：
python scripts/benchmark.py /tmp/shiwen-benchmark-pilot --documents 100
```

脚本只生成和读取指定目录中的合成文件，不读取个人文档。默认完整轮次写入 `report.json`，查询轮次写入 `search-report.json`。最终发布代码默认得到优化后的查询数据；已提交的 baseline JSON 保留本次优化前实测，不能把它当作最终代码的查询结果。

## 尚未验证的目标

PRD 的参考环境是 4 核 / 8 GB，语料比例和查询规模也与本次不同。仍需补充代表性真实文档、40% PDF / 40% Markdown / 20% DOCX、至少 100 条查询、完整 GUI 的空闲 / 峰值内存、冷缓存及 Windows / macOS 实测。本文不能据此宣称所有万文档场景都低于 300 ms，或整个应用内存低于 100 MiB。
